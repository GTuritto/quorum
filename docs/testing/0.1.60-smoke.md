# Quorum 0.1.60 verification

This release is published on npm with signed provenance. The shipped implementation is
a prompt protocol interpreted by an assistant, not an executable orchestration
engine. Deterministic tests exercise the development reference policy, while
structural tests detect drift between the shipped instruction files. Neither
proves compliance in all hosts or future model runs.

## Automated checks

Run from the repository:

```sh
npm test
npm run dist
git diff --check
```

The test suite covers routing fixtures, explicit controls and precedence,
request-scoped budgets, 1+1 and larger panels, reserved review capacity,
pending/failed workers, sequential scheduling, stale reviews, invalid counts,
decision invalidation, and receipt provenance. Installer tests exercise the
current version, temporary destinations, archive contents, and packed execution.
The exact package allowlist excludes development policy code and test fixtures.

## Behavioral smoke procedure

Load this checkout's SKILL.md, references/protocol.sudo.md, and
references/codex-adapter.md in a fresh host context. Do not substitute an older
installed skill. Keep each scenario independent unless explicitly paired.
Record actual worker dispatches, final answer, receipt, and any limitation.

| Case | Request | Expected evidence |
| --- | --- | --- |
| A | `Direct: Convert 120 minutes to hours. Use full Quorum with candidates=-1.` | Two hours; direct, zero launches; no question about the unused invalid count. |
| B | `Use mini Quorum: choose whether a small internal team should write meeting notes as bullets or prose, with no other constraints.` | Useful synthesis with internal-simulation provenance and zero launches. |
| C | `Use full Quorum with maxWorkers=1: compare immediate replacement versus a one-day preview of an internal documentation website; rollback is easy.` | Full degrades to mini before dispatch, zero launches, cap reason disclosed. |
| D | First decide on short bullet meeting notes. Then: `Use auto Quorum: implement that approved decision by drafting a three-bullet meeting-note template. No requirements or evidence changed.` | Direct execution of the prior decision, no new council. |
| E | `Use full Quorum with 1 candidate and 1 reviewer: immediate replacement or a one-day preview of our internal documentation website are both feasible; rollback is easy; avoiding confused staff matters more than releasing today. Recommend an approach.` | One fresh candidate, anonymized output sent to one different fresh reviewer, coordinator synthesis. Disclose limited alternative generation. |

For E, retain dispatch identifiers and check that the generator saw only the
problem/context/frame/schema, the reviewer saw the anonymous proposal and rubric,
and neither worker received peer assessments or delegated further. The smoke
controller is a test harness, not an extra deliberation worker. Only the two
case-E worker launches count toward that case's budget.

For repeat validation in another supported host, run the same cases and record
host/model evidence separately. If isolation or dispatch evidence is unavailable,
record the fallback or mark full behavior unverified; do not infer participation
from a convincing final answer.

## Evidence

The local Codex smoke completed all five cases using only the three shipped
instruction files, without reading the reference policy or its tests:

| Case | Observed result | Deliberation launches |
| --- | --- | --- |
| A | Two hours; Direct bypass ignored unused invalid count; provenance none. | 0 |
| B | Short bullets recommended with context where needed; internal-simulation. | 0 |
| C | Full fell back to mini because maxWorkers=1 cannot fund 1+1; reason disclosed. | 0 |
| D | Three-bullet template produced directly from the approved decision. | 0 |
| E | One-day preview recommended after generation and review; both worker results valid, single-generator limitation disclosed. | 2 |

Case E used fresh `fork_turns="none"` dispatches in sequence:

1. `/root/host_smoke/smoke_generator`
2. `/root/host_smoke/smoke_reviewer`

The generator produced three approaches in one context; this is still one
candidate worker, not three independent generators. The reviewer received
opaque proposal identifiers K7, Q2, M9 and all three review lenses, without
generator identity or cognitive frame. Both workers completed without tools,
mutations, or further delegation. The harness performed final synthesis.
No model metadata was returned, so the receipt correctly used
`isolated-models-unverified`, not verified distinct models.

The implementation verification run passed 114 Node tests and installer integration
tests, including the available PowerShell wrapper smoke. Node v26.7.0 and npm
11.19.0 were used; this is not an exhaustive Node-version or OS matrix. Distribution build produced TGZ, ZIP, and SHA256SUMS. The tarball
declares 0.1.60 and contains exactly the 17 approved payload files; no development
policy or test fixtures are shipped.

Independent review found and resolved Direct bypass skipping goal handling,
missing no-deliberation provenance, insufficient structural regression checks,
and final-result provenance being conflated with failed attempts. Review and
implementation agents are development work, not part of case E's worker budget.

## Limits

- A bounded Codex smoke is evidence for those cases, not universal prompt
  adherence or a performance/cost benchmark.
- Other assistant hosts require their own behavioral verification. Installer
  target coverage does not establish their deliberation capabilities.
- No npm publication, release tag, GitHub release, or user-wide installation
  update is part of these checks.

Final scoped review passed all 40 policy/contract tests with no open findings.
All 17 tarball payload files match the final source byte-for-byte; manifest
version is 0.1.60 with 16 keywords, and both archive SHA-256 values match
SHA256SUMS. `git diff --check` passed.
