## Case A

**Prompt**

> Use auto Quorum to explore unusual ways to reduce onboarding friction for a
> six-person software team. Keep our existing documentation tools and spend no
> money.

**Actual user-facing answer**

Recommendation: start with a one-page role-based “first useful change” path in
the existing docs, then test a reversible “confusion bounty” that asks each new
starter to mark the first three places where the path fails.

- Baseline: shorten the current onboarding checklist to the minimum steps needed
  for one useful contribution. Mechanism: remove early reading that is not needed
  for that contribution. Evidence: workflow analogy only; local benefit is
  unverified.
- Alternative: add a choose-your-role entry page that links to existing material
  instead of duplicating it. Mechanism: reduce search choices at the start.
  Evidence: information-foraging analogy; effectiveness here is a hypothesis.
- Alternative: run a “broken trail” exercise in which a teammate follows the
  path literally and annotates every ambiguity in the existing tool. Mechanism:
  expose tacit knowledge through observed failure. Evidence: no local data yet.

Hard constraints: use current documentation tools; zero spend; suitable for a
six-person team. Small test: have the next starter and one current teammate each
use the new path for 30 minutes. Support means both reach the first contribution
without verbal rescue and identify at most two blocking ambiguities. Reject or
revise if either cannot finish or needs repeated help.

Receipt: Quorum requested auto; actual mini; exploration requested auto;
explorationApplied=true; 0 candidates + 0 reviewers launched, 0 total launches;
internal-simulation; synthesis: coordinator.

**Evaluation**

Pass. Three mechanisms are materially different: scope reduction, role-based
navigation, and observed trail failure. Claims are labeled as analogy,
hypothesis, or unverified. Both hard constraints remain binding. The experiment
has observable support and rejection conditions.

## Case B

**Prompt**

> Use mini Quorum to brainstorm ways a neighborhood book club can welcome
> quieter members. No paid tools, extra meetings, or mandatory speaking.

**Actual user-facing answer**

Recommendation: let members contribute before and during the existing meeting
without putting anyone on the spot.

- Baseline: the host shares one optional question in the club's current message
  channel; replies may be private or public.
- Alternative: place three handwritten prompt cards on the table and let anyone
  silently add a note or check mark.
- Alternative: use a voluntary “pass, add, or ask” round inside the current
  meeting, with passing treated as complete participation.

These ideas assume the club already has a message channel and basic paper. Their
effect on quieter members is unknown; no participation benefit is claimed yet.
Consent rules: every contribution mode is optional, private responses are quoted
only with permission, and silence is never treated as agreement. Constraints:
no paid tools, no new meeting, no mandatory speech.

Test for two regular meetings: offer all three modes and anonymously ask one
yes/no question afterward: “Did you have a comfortable way to contribute?” Keep
the approach only if opt-in participation broadens and nobody reports feeling
pressured; remove or revise any mode linked to pressure.

Receipt: Quorum requested mini; actual mini; exploration requested auto;
explorationApplied=true; 0 candidates + 0 reviewers launched, 0 total launches;
internal-simulation; synthesis: coordinator.

**Evaluation**

Pass. The answer stays non-technical, preserves consent, labels assumptions and
unknown outcomes, and satisfies all three prohibitions. The trial has an
observable outcome and a rejection condition.

## Case F

**Scenario precondition**

An earlier decision selected a documentation index under the same constraints.

**Prompt**

> Use auto Quorum to explore new alternatives under the same constraints.

**Actual user-facing answer**

The request for new alternatives invalidates reuse of the earlier index decision.
Assumed unchanged constraints: use existing documentation tools, add no service,
and do not move data.

Recommendation: retain the index as the comparison baseline and test a
question-led “where would I look?” path first.

- Baseline: maintain the previously selected documentation index.
- Alternative: add task-question entry links inside the existing docs, such as
  “How do I release?” Mechanism: start from user intent rather than document
  location. Evidence: navigation analogy; local effect unverified.
- Alternative: add lightweight “related next” links at the end of high-traffic
  documents. Mechanism: expose useful adjacency without central cataloguing.
  Evidence: hypothesis; traffic and maintenance cost are unknown.

Experiment: choose ten recurring documentation tasks and have representative
users attempt them with the index and question-led path. Support for the
alternative means higher first-click success and no increase in median task
time; reject it if either measure worsens or link upkeep cannot be assigned.

Receipt: Quorum requested auto; actual mini; exploration requested auto;
explorationApplied=true due to explicit new alternatives; 0 candidates + 0
reviewers launched, 0 total launches; internal-simulation; synthesis:
coordinator; prior decision not reused as the answer.

**Evaluation**

Pass. Fresh exploration occurs despite the compatible prior decision. The index
is only the baseline, alternatives use distinct mechanisms, constraints remain
binding, evidence is qualified, and the comparison is observable.

## Case G

> documentation index.

**Actual user-facing answer**

Recommendation: run a bounded pilot before adopting the fixed documentation
index. The proposal is plausible if ownership and update triggers are explicit,
but its value cannot be established from the description alone.

Analyst: a single index can reduce uncertainty about where documents live.
Supported input: the proposal is an index. Unsupported claim: that it will
improve discovery in this organization.

Skeptic: the main failure mode is stale links or incomplete coverage creating
false confidence. Reconsider if maintenance ownership is absent or if users
still bypass the index.

Pragmatist: pilot one bounded documentation area using existing infrastructure.
For ten representative lookup tasks, compare first-click success, completion
time, and broken or missing entries before and after. Support adoption if
first-click success improves without slower completion and every stale entry has
an owner; reject or revise otherwise.

**Evaluation**

documents plus three copyable queries for the search tools you already have. It

new service or data movement, but its feasibility depends on current search
actually indexing the chosen metadata.

Keep `Q7M4`, a minimal index in an existing README, as the practical fallback and
comparison baseline. `R2K9` is worthwhile for one recurring multi-document

is inconsistent, or metadata upkeep has no clear owner. Expected effort: a
bounded sample and several representative lookup tasks, without changing paths.

Key uncertainty: no local search behavior, user-entry data, or maintenance cost
was supplied, so the recommendation is an experiment rather than a claim of
proven superiority. The reviewer’s minority view favors the baseline index
because it is cheaper and rests on fewer assumptions.
