# Quorum 0.1.65 verification

Status: Local implementation verified on 2026-09-18; not published.

The shipped behavior is a prompt protocol interpreted by the host. The Node
reference policy models normalized semantic inputs; it does not execute prompts
or enforce arbitrary host behavior. Structural checks detect document drift,
not creativity or universal compliance.

## Automated procedure

Run `npm test`, `npm run dist`, and `git diff --check`. Inspect the tarball's
version and exact allowlist. Current-version README commands must agree with
VERSION, package.json, and SKILL.md. Historical release fixtures stay intact.

## Behavioral procedure

Read the checkout's SKILL.md, references/protocol.sudo.md, and Codex adapter.
Use independent scenarios and preserve the prompts, concise final artifacts,
actual dispatches, and receipts. Do not use hidden reasoning as evidence.

| Case | Request | Required observations |
| --- | --- | --- |
| A | Use auto Quorum to explore unusual ways to reduce onboarding friction for a six-person software team. Keep our existing documentation tools and spend no money. | Mini, zero workers; baseline and distinct alternatives; hard constraints; observable experiment. |
| B | Use mini Quorum to brainstorm ways a neighborhood book club can welcome quieter members. No paid tools, extra meetings, or mandatory speaking. | Non-code ideas; consent and constraints preserved; no invented evidence; testable experiment. |
| C | Use full Quorum with exploration on and maxWorkers=1 to explore ways to make our existing internal search tool easier to use. | Degrade to mini before dispatch; exploration remains applied; zero launches; disclosed cap. |
| D | Direct: brainstorm three ways to improve meeting notes, exploration=invalid and candidates=-1. | Normal creative answer allowed; structured exploration bypassed; no invalid-control clarification or workers. |
| E | Use full Quorum with 1 candidate and 1 reviewer, exploration on, to improve internal documentation discovery without new services or moving data. | One isolated generator bundle, opaque option IDs, one fresh reviewer, coordinator synthesis; limited independence disclosed; two launches. |
| F | After an earlier decision to use a documentation index, ask: Use auto Quorum to explore new alternatives under the same constraints. | Prior decision does not suppress fresh exploration. |
| G | Use Quorum with exploration off to evaluate a fixed proposal for a documentation index. | No creative option-generation contract forced; ordinary routing remains in effect. |

For E, the reviewer receives anonymized options, necessary problem context, and
all three review lenses without generator identity or frame. Neither generator
nor reviewer may delegate, mutate tools, or inspect peer assessments. The smoke
harness is separate from the case's two deliberation launches.

Judge actual options for distinct mechanisms, usefulness, evidence labeling,
constraint compliance, and a falsifiable experiment. Do not award semantic
quality merely because expected terms appear. Originality means relative to the
baseline, not proof of a globally new idea.

## Evidence and limits

All 135 Node tests and installer integration tests passed on Node v26.7.0,
npm 11.19.0. Distribution build and diff checks passed. All 17 tarball payload
files match the final source byte-for-byte, package metadata declares 0.1.65,
and both archive hashes match SHA256SUMS.

The first full run exposed two stale 0.1.61 regex expectations in installer
output tests. Updating those expectations resolved both failures; installer
behavior was unchanged.

All seven behavioral cases passed. [Recorded prompts, answers, receipts, and
review artifacts](0.1.65-smoke-results.md) preserve the evidence. Cases A/B/C/D/F/G
used independent simulated scenario state in one harness context, so they do
not establish cross-case isolation. Case E used fresh `fork_turns=none` workers:
`/root/creative_smoke/case_e_generator` and
`/root/creative_smoke/case_e_reviewer`. Exactly two deliberation launches produced
one option bundle and one independent review. Four opaque option IDs were
reviewed through all three lenses; source mapping remained private. The
conditional option did not win, and a useful minority view survived synthesis.
Model identity was not verified; receipt provenance is
`isolated-models-unverified`.

Independent review resolved ordinary/off-mode routing ambiguity, explicit-direct
validation wording, three-lens mini review, per-option uncertainty preservation,
and mode-specific review identifiers. Final scoped review reported no open
findings. Development/review agents are separate from smoke worker counts.

Other hosts and a full operating-system/Node-version matrix remain unverified.
Prompt compliance and creative quality can vary in later runs. This release does not add memory, learning, a specialist
catalogue, installer flags, or token/currency accounting. Publication and
user-wide installation updates are outside implementation verification.
