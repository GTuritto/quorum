# Quorum 0.1.84 release verification

Date: 2026-10-31. This release contains the Codex mode-choice prompt and the
Update backup placement fix. It does not add the capabilities previously
proposed under the historical 0.2.0 label.

## Fresh Codex CLI check

A source-built 0.1.83 skill was installed in a disposable project and invoked
in a fresh Codex CLI 0.160.1 session with read-only sandboxing and no workers.
The explicit `$quorum` request loaded the skill entry, core and Codex adapter,
then presented Auto, Direct, Mini, Full and Super with their relative worker and
use implications. It asked for a choice before reviewing the supplied arithmetic
task. No worker was launched and no file was written. The CLI run did not test
the desktop picker, a follow-up choice, or all mode/fallback cases in
`mode-choice-smoke.md`.

## Update and memory check

The published npm 0.1.83 tarball was installed into a separate disposable Codex
project. Project memory was enabled and one test decision was saved. An older
backup was placed beside the skill to exercise migration. The 0.1.84 source
installer updated the skill, moved that backup and its new replacement backup
to the sibling `.agents/skills.quorum-backups/` directory, and left exactly one
`quorum` directory discoverable under `.agents/skills/`. The installed `VERSION`
reported 0.1.84. The memory setting remained enabled and the saved decision was
readable by query after the update. This was a disposable project; the real
user installation was not changed.

## Release gate and limits

The release candidate passed 196 automated tests and installer integration on
Node.js 26.7.0, plus `TZ=UTC npm run dist`, `git diff --check`, and both archive
checksums. The fresh desktop picker, broader
Codex/Claude host behavior, automatic-capture eligibility, and effective Super
model/effort verification remain outside this bounded check. Structural tests
and this CLI run do not establish universal host compliance. These limits should
be reflected in the release communication and any GitHub release notes.

## Fresh Codex CLI follow-up: 2026-11-06

Quorum 0.1.84 was installed from the current source into a new disposable
project. Four separate `codex exec --ephemeral --skip-git-repo-check --json`
processes used Codex CLI 0.160.1. The first Direct case used a read-only
sandbox; the other cases used a workspace-write sandbox limited to the project.
Only tool actions, final messages, and helper results were inspected. No desktop
picker, Claude host, worker dispatch, or effective Super setting was tested.

| Case | Observed result |
| --- | --- |
| Explicit Direct arithmetic | Passed: entry, core, and Codex adapter loaded in order; answer was correct; receipt reported Direct, zero workers, cap 4, no model provenance, and no exploration. |
| Turn project memory on | Storage passed: `on` and a separate `status` returned `enabled: true` for the disposable project. Loading order failed: the host ran project and memory searches after reading the entry but before loading the core. |
| Meaningful Direct decision while memory was on | Capture passed: the host loaded memory rules, called the helper once, and a separate bounded helper read returned one historical, unvalidated record. Loading order failed again: project search preceded core loading. The final response gave only “Direct: 0 workers” instead of the full required receipt and said no files changed although the memory store was written. |
| Second Direct decision while memory was on | Loading order failed again: project search preceded core loading. The final receipt was complete. No memory module or capture occurred; this single case does not establish whether the host judged the decision ineligible or missed an eligible capture. |

These are bounded host observations, not a general pass for automatic capture.
The storage helper behaved as expected in the capture case, while instruction
ordering failed in three fresh processes and final reporting was inconsistent.

### Entry-wording trial

An unreleased candidate made the entry instruction more explicit: read the core
and Codex adapter immediately, before Git, project inspection, or memory search.
A separate fresh CLI process installed that candidate in another disposable
project and requested memory `on`. Codex ran `git status` before reading the
skill entry, then searched project files before reading the core. The setting
and status helper calls succeeded and the final receipt was complete. The
wording change was reverted because it did not repair the observed ordering.
This trial does not establish that prompt wording alone can enforce the gate;
investigate the host activation path and record residual limits before making
a stronger compliance claim.
