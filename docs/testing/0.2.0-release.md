# Quorum 0.2.0 global-memory release verification

Date: 2026-11-07. Status: published with the host limitations below. The
[0.1.86 workflow](https://github.com/GTuritto/quorum/actions/runs/42344032978)
and [0.2.0 workflow](https://github.com/GTuritto/quorum/actions/runs/42344222433)
both passed. npm reports 0.2.0 as latest and exposes its package integrity and
signed provenance. The downloaded 0.2.0 tarball includes both memory helpers.

## Scope

This release adds a separate local user global-memory store. It supports
global on/off/status, explicit share of one project record, destination preview
and admission with the previewed digest, requested historical read, destination
revocation, linked-global-ID lookup, and exact-scope global forget. Existing
schema-v1 project records and settings remain project-local. Global enablement
does not promote or capture them. Automatic global capture and validated reuse
remain out of scope.

The helper binds a snapshot to the source record and project identity. A
destination admission binds its own project identity. A requested read reports
the original record, provenance, uncertainty, admission ID, and the source
record state observed at read time. A source deletion or unavailable project
does not silently validate or remove an explicitly shared snapshot. Project
forget and global forget affect their selected scopes only.

## Verification and limits

The candidate's new deterministic tests cover explicit authorization, project
off and global off, share retry, preview digest, admission, read, destination
revocation, project/global forget, copy/rename/source loss, malformed storage,
links, lock/residual writes, permissions, CLI parsing, and packed installation.
The [smoke procedure](0.2.0-smoke.md) lists fresh-host checks still required.

On 2026-11-06, `npm run quality:record` passed 210/210 Node tests, installer
integration, benchmark corpus validation, the distribution build, both archive
checksums, and `git diff --check`. The [append-only QA snapshot](../../benchmarks/results/2026-11-06T21-53-15-661Z-d79e968f-7ce89009.json)
records the exact checks and explicitly marks decision-quality benchmarking
as not run.

A disposable upgrade from the merged 0.1.86 source to the 0.2.0 candidate
preserved a schema-v1 project record. The old 0.1.86 helper still read that
record after a global snapshot was created, and its read left the separate
global store intact. This is one bounded upgrade/rollback-compatibility check,
not a claim about every host or filesystem.

## Bounded fresh Codex CLI status follow-up

A disposable project installed the source-built 0.2.0 candidate, then ran two
separate read-only `codex exec --ephemeral --skip-git-repo-check --json`
processes. Both requested only global status. The first process read Git and
task memory before the core rules and then failed with a model-capacity error
before a helper call. The second process, using `gpt-6-luna`, read a user-wide
older skill entry, the project entry, and task memory before the core; it then
loaded the core, adapter, and memory module. Its helper call returned global
`enabled: false`, and the final answer accurately reported off and no changes.
The user-wide global directory remained absent. This confirms a bounded
status result, while reproducing the loading-order failure in both processes.
The final answer did not contain Quorum's complete required mode receipt.

No fresh Codex or Claude host run has verified the share, preview, admission,
read, revocation, or forget flow. The earlier 0.1.84 Codex CLI loading-order
and receipt failures remain relevant. The user authorized publication with
these known limits on 2026-11-07. Do not claim host-wide global-memory
compliance. Keep the remaining fresh-host cases open as follow-up verification.
