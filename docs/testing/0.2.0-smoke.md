# Quorum 0.2.0 global-memory smoke procedure

Status: published with host acceptance pending. A read-only Codex CLI global-status follow-up
is recorded in [release evidence](0.2.0-release.md), including loading-order
and receipt failures; the full host flow remains pending. Use disposable projects and a disposable home; never test with
real user memory. Record the host/version, installed source revision, task,
actual helper calls, final text, and receipt for each case. Preserve failures.

## Helper and packed-install gate

Build and install the candidate package into disposable project A. Confirm the
installed `references/memory.mjs` and `references/global-memory.mjs` match the
source files. Create a synthetic project record that preserves an assumption,
uncertainty, source, and reconsideration condition. Use another disposable
project B and a third project C. Point the test process's `HOME` at the
disposable home so global data cannot touch the user's actual local store.

| Case | Required observation |
| --- | --- |
| Default global off | Status reports off without creating storage; project records remain local. |
| Global on, project off | On creates only global settings. No record is promoted; share requires a separate exact-record authorization and one-time project-off override. |
| Share and retry | One snapshot is created with global ID and digest; retry after lost receipt returns that ID without a second copy. |
| Preview and admit | B previews the exact global ID and digest as historical/unvalidated; B admits with that digest. A mismatched digest fails. |
| Requested read | B's explicit read names source, destination, admission ID, and source-record state. C cannot read before its own admission. No automatic read occurs. |
| Destination revoke | B loses access while global snapshot and other admissions survive. Revocation still works while global is off. |
| Project forget | A's selected record is removed; an explicitly shared global snapshot survives and the answer discloses that scope. |
| Global forget | Snapshot and every admission are removed; A's source record survives if not separately forgotten. |
| Rename, copy, unavailable source | Copy/replacement inherits no admission; missing source cannot be shared, while an already admitted snapshot remains labelled historical. |
| Failure paths | Foreign schema, links, broad permissions, lock contention, interrupted write, and missing home fail without claiming success or broadening scope. |
| 0.1.86 update and rollback | Existing schema-v1 project records remain readable; no implicit migration or deletion. Older helper does not manage the separate global store. |

## Fresh-host acceptance

Install the source-built candidate in a fresh Codex session, then a fresh Claude
Code session if release claims include Claude. Request on, share, preview,
admit, read, project forget, and global forget in separate bounded sessions.
Check that the entry and core load before task tools, the memory module loads
before affected actions, helper arguments express the exact scope and explicit
authorization, and the final receipt matches the actual result. Use a second
case with project capture off and a separate one-record share override. Exercise
a copied destination and an unavailable source. Record any ordering or receipt
failure as a host limitation; passing helper tests alone cannot close it.

The 0.1.84 Codex CLI follow-up found core-loading and receipt failures. Do not
interpret a successful helper call or plausible answer as proof those host
failures are repaired. No 0.2.0 host pass is claimed until the fresh sessions
above are observed and recorded.
